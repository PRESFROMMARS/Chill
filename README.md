# Chill

基于 `engine.py` 的桌面轨迹工作台。`main.py` 使用 pywebview 创建 1380 × 860 窗口；
`ui/index.html` 提供中文与英文地图编辑器、实时仪表和三段安全流程。

## 名称与图标

应用名称为 Chill。狗狗图标位于 `ui/assets/`，包含 PNG、Windows ICO 和 macOS ICNS。
Windows 构建将 ICO 嵌入 `Chill.exe`；网页标题、页眉及浏览器图标使用同一品牌。
为兼容已有模板，配置文件仍保存在 `~/.pace_config.json`；内部令牌与隧道参数保留原标识。
图标生成说明见 [图标记录](artifacts/chill-brand/README.md)。

## 启动

Windows 用户可在本仓库的 Releases 下载 `Chill-Setup.exe` 安装程序，或下载并完整解压
`Chill-Windows-Portable.zip`。安装程序保留与便携版相同的完整目录结构。
发布 `v*` 标签时，GitHub Actions 在云端执行 Windows/macOS 测试、Windows 打包和沙盒冒烟测试，
全部通过后才发布 Release。维护者的 Mac 不参与 Windows 构建，也无需下载产物。

建议使用 Python 3.13；Windows 构建固定使用 3.13 x64。安装完整依赖后，在 Mac 上可直接预览：

```sh
python -m pip install -r requirements.txt
python main.py --sandbox
```

连接真机时使用同一套依赖：

```sh
python main.py
```

无 pywebview 也可运行同一套界面与后端的浏览器预览：

```sh
python main.py --preview --sandbox --port 8765 --config ./preview_config.json
```

在浏览器打开终端显示的回环地址。预览使用真实的本机运动引擎，不会连接手机。
浏览器标签页的关闭限制由浏览器决定；真正的原生窗口使用 pywebview `closing` 事件拦截。

已按卫星红色跑道校准的公开示例，可用下面的命令复现多圈预览；配置写入临时目录，
不会覆盖个人模板：

```sh
python scripts/preview_calibrated.py --port 8770
python scripts/verify_alignment.py
```

第二条命令执行不同随机种子和窄跑道的八圈边界验证，报告保存在
`artifacts/alignment-verification.json`。这是人工对齐的示例场地；自己的场地需沿红色跑道
中线绘制基准线，并设置实际可用总宽度（1～8 米）。程序不会从底图自动识别塑胶边界。

## 安全流程

1. 在地图上添加至少三个跑道锚点，拖拽微调后保存。默认目标为两公里。
2. 点击锁定起点，逐项确认七项自检。外部校时不可达时，第五项由用户核对电脑与手机时间。
   起点坐标发送成功后，后端才开始五秒驻留。期间断连会取消倒计时，需放弃会话并恢复后重试。
3. 在巡航中切换“支线草稿”，沿道路添加引路点，选中点后勾选必经打卡点。
   金色虚线不会改变当前运动；确认后，后端才会沿操场前往出口，再执行支线。
4. 先在手机应用提交并确认成功，彻底关闭手机应用，再点击“安全结算并恢复”。
   三项确认全部完成后，后台停止运动并请求清除模拟定位。
   发送恢复指令失败时，窗口仍会受到保护，可以重试。发送成功后请在 iPhone 自带「地图」中核对真实位置。

目标里程用于提示和触发收尾慢走。勾选“允许少量超出目标”后，锁定时随机增加零至目标的 3%，最多 60 米；
锁定后、开始巡航前显示输入目标、额外米数和实际目标。普通跑道在目标前约 12 米开始平滑转为慢走，
达到目标后继续沿外道移动，直到手动执行第 4 步。此期间实际里程和用时继续累计，超出距离没有自动上限。
已经确认的支线会先完成，再回到跑道转为慢走。收尾慢走不会自动恢复跑步，也不接受恢复或新增支线。
暂停慢走或收尾慢走时可选择「原地驻留（定点保活）」。尚未提交的会话可放弃并安全恢复定位。
运动引擎异常会显示持续错误提示；锁定或恢复失败的原因显示在当前弹窗内，支持重试。
手机断开期间无法保证物理坐标发送，也不能保证第三方应用的记录或账户结果。

## 慢走喘气模式

巡航面板顶部的“歇一下（切换慢走）”在约 5.5 秒内余弦过渡至慢走，保持沿路线移动。
慢走基础速度为 1.35～1.55 m/s，叠加幅度不超过 0.12 m/s 的平滑呼吸项；巡航指令限制在
1.20～3.80 m/s，每秒变化不超过 0.55 m/s。默认约 40～60 秒后自动恢复，也可点击“恢复慢跑”，
以约 8 秒余弦过渡恢复。控制冷却为后端和前端共同强制的 1.5 秒；切换阶段拒绝连点。

未访问必经点前 10 米平滑降速至正常值的约 73%。到达时单独发送距中心至多 8 厘米的关键坐标，
截断该 Tick 剩余行程；当次速度可以低于常规下限，下一 Tick 按实际速度限加速恢复。
关键坐标按运动顺序保留至设备发送调用成功，重连不会用最新普通点覆盖它；设备故障或熔断仍可能阻止送达。

默认宽跑道慢走向外偏移约 1.8 米，恢复后回到常规跑线；窄跑道以校准的可用宽度为上限。
慢走仍累计实际里程和运动时间，“累计慢走”是总用时的一部分，不再重复叠加时间。
已经确认的支线仍保留；支线只沿其道路几何前进，不向道路外强行偏移。

设备桥接限制每步位移最多 3.8 米。移动和驻留的发送从上次开始计时，至少间隔 0.8 秒，并等待前一次调用完成。
后台每 Tick 最多推进 1 秒，卡顿超出部分丢弃不追赶；上一点未发送完成时冻结运动，按消费节奏生成后继点。
队列保持相邻运动点的顺序，满队列仅合并仍能在 3.8 米内衔接的中间普通点，不删队头或关键点。
必要前导链无法合并时，以一个额外保留槽接纳关键点并暂停生产；全关键点或超出有界容量仍熔断。
突跳也会锁存熔断，
停止坐标发送并明确提示安全结算；重连不会绕过上一次发送坐标的基线。
发送延迟和积压会显示提示。USB/网络故障、休眠和系统调度可能破坏实际频率，不能保证真实设备始终 1 Hz。
真机模式必须先连上手机才能锁定，无法连接时请显式使用沙盒预览。

`python test_audit.py` 执行离线压力审计，报告位于 `artifacts/chill-audit-terminal.txt` 和
`artifacts/chill-audit-report.json`。这些工程阈值不等于第三方 App 的反作弊规则，测试不证明账号不会受限。

## 配置与系统保护

- 默认配置保存至 `~/.pace_config.json`。支持语言、GCJ-02 跑道、跑道总宽、档位、目标、图层和视图位置。
  写入采用同目录临时文件、同步和原子替换；失败不会破坏现有配置。
- 有效跑道编辑会自动保存，保存按钮可立即保存；清空可使用撤销恢复。
- Windows 在独立线程上设置 `SetThreadExecutionState(0x80000003)`，退出时在同一线程恢复。
- macOS 启动 `caffeinate -di -w <主进程 PID>` 防止显示器和系统闲置休眠；正常退出会回收该子进程，
  主进程异常退出后绑定的断言也会释放。保护启动失败或提前退出会报告防休眠失败。
- 本地界面服务只监听回环地址。Windows 便携包启动时由系统显示管理员授权提示。
- Windows 真机模式会检查 `Apple Mobile Device Service`，将已安装但停止的服务设为自动并尝试启动。
  缺少驱动或自动启动失败时才显示对应提示。
- 真机还需要设备信任配对、开发者模式与适用驱动。缺失条件时引擎回退沙盒。
- 多台设备同时连接且未指定 UDID 时直接拒绝自动选择。连接准备阶段也显示具体的驱动、权限或隧道错误。
  自动缓存可在安全状态下失效重选；存在未恢复定位的脏会话时必须重新连接原手机。
- 控制手机前获取按 UDID 区分的进程文件锁，修改配置路径也不能绕过同设备互斥；冲突时显示“检测到另一个程序实例正在运行，请勿多开”。
  脏标记写入另外使用原子事务锁，清除定位前先核对设备和标记归属。锁文件不删除，进程退出后由操作系统释放锁。
- 首次发送虚拟定位前，会在配置旁写入恢复标记（默认 `~/.pace_config.location-session.json`）。
  只有确认清除定位后才删除；发送失败或退出恢复失败会保留。下次启动将提示“上次异常退出，定位可能未恢复”，
  暂停新会话，并提供“连接上次设备并恢复定位”按钮；请连接原来的 iPhone 后重试。
  沙盒不会清除真机标记，无法读取的标记会提示维护处理。
- 正常退出、SIGTERM 和 Windows 控制台关闭共用清理流程，先尝试重连清除，再关闭设备通道。
  默认清除重试窗口为 6 秒，Windows 控制台关闭回调为 3.5 秒；结果写入日志。
  强制结束、断电或断线仍可能来不及清除，请在下次启动时使用恢复按钮。
- 打包发布时，将 `ui/` 整体包含在包内；PyInstaller 路径通过 `_MEIPASS` 解析。
  冻结程序通过专用子进程入口启动内置 Tunneld，运行在同一管理员权限下，详见 [引擎说明](ENGINE.md)。
- 自建隧道每 0.5 秒检查父进程，父进程消失后终止自己的进程组；Windows 同时使用 Job Object 约束后代。
  同步驱动使用有数量上限的守护线程，退出不等待永久阻塞的调用；未确认定位恢复时仍保留脏标记。
- 故障摘要保存在配置所在目录的 `Chill/last_session.log`（默认 `~/Chill/last_session.log`）。
  只记录连接失败、熔断和异常摘要，最近重复错误会合并；单文件最多 256KB，不生成历史日志堆积。
  无控制台的隧道子进程恢复父进程传入的输出管道，错误不会再被写入空设备。
- 路线自适应细分及采样最多 25,000 点；普通构建预算 2 秒，运动锁内重建预算 250ms。
  超限时拒绝过于复杂的支线，或临时沿用安全的上一圈形状，界面提示缩短路线或减少选点。

## 聚光灯新手教程

顶部「✨ 新手教程」可随时重播五步引导。启动读取配置后，如果尚未保存默认跑道，
会自动打开教程；已有默认跑道时不会自动弹出。不额外保存教程完成标记。
教程支持直接使用高亮区域、中文和英文同步切换、上一步、下一步、跳过与 Esc 退出。
它只引导界面操作；后台巡航继续运行，关闭保护和结算确认始终优先。

原有六项开跑自检全部保留，新增第七项天气与校园开放时段确认；后端也会校验七项确认。
结算弹窗提醒先在手机提交并关闭应用，再从电脑发送恢复指令。在 iPhone「地图」中确认定位后再拔线。

## 多圈预览

右侧新增当前圈数和上一圈用时、配速，原来的已完成圈数继续保留。
每圈采用微扰后的样条；横向位置持续随机游走，并周期性平滑借道。
用户跑道锚点会先过滤过密普通点并做一次有限幅的局部预平滑，必经点坐标受保护；逐圈重建不会重复此步骤。
蓝白色历史线显示实际运动位置，与蓝色跑道模板分开绘制，地图放大后可观察细节。
后端和前端均保留最多 3600 个样本，窗口恢复或页面重载会补取历史，避免最小化丢线。
按 0.8 秒采样约可保留 48 分钟。算法和圈速统计约定见 [引擎说明](ENGINE.md)。

## Windows 便携版

将代码推送到 GitHub 后，`Build Windows Portable` 工作流会自动运行；也可以在
仓库的 **Actions → Build Windows Portable → Run workflow** 手动运行。
成功后，在该次运行底部的 **Artifacts** 下载 `Chill-Windows-Portable`，获得
`Chill-Windows-Portable.zip`。完整解压后双击 `Chill.exe`，保留旁边的 `_internal` 文件夹。
朋友版配图说明见 [README_FOR_HER.md](README_FOR_HER.md)，也会放入便携包。

构建使用 PyInstaller 的 `--onedir --noconsole --uac-admin --noupx`，收集完整 `ui/`、
`pymobiledevice3` 子模块、依赖元数据与隧道资源。CI 在 Windows 上运行单元测试，
检查冻结程序的沙盒、隧道命令、userspace RSD、DDI 和 DVT 导入，再校验静态资源、
生成文件哈希清单并压缩。
文件夹打包不能保证消除安全软件的全部误报；本项目没有代码签名证书。

在 Windows 源码目录安装 `requirements-build.txt` 后，先准备离线镜像，再运行工作流中的
PyInstaller 命令。工作流会把两套镜像从 `assets/ddi/` 打进 `_internal/assets/ddi/`。

```powershell
python scripts/package_windows.py --prepare-ddi
# 在此运行工作流中的 PyInstaller 命令。
python scripts/smoke_windows.py dist/Chill/Chill.exe
python scripts/package_windows.py
```

发行包直接使用校验通过的驱动缓存或内置镜像。iOS 27 真机使用 Cryptex 时也从本地读取镜像，
首次个性化可能仍需访问 Apple TSS 签名服务。构建和未打包的源码可在下载失败时自动尝试镜像站，
所有镜像文件均以固定上游修订和 SHA-256 校验。

Windows 便携包需要 Apple Devices 驱动、设备信任与开发者模式；首次使用还可能需要
Microsoft WebView2 Runtime。Windows EXE 需要在 Windows 环境构建，Mac 验证不代表真机验收。

## 地图与搜索

地图默认叠加高德卫星瓦片与透明路网标注，也可切换标准街道图。
锁定时从第一个锚点开始。锁定前可在路线编辑器调整经度和纬度偏移，每步 1 米。
经度正数向东，纬度正数向北。点击「应用微调」后，蓝色预览线会显示平移后的路线。
Leaflet 1.7.1 的脚本和样式均从 `ui/vendor/` 本地资源加载。
本地 Leaflet 也不可用时，原生坐标画布仍支持点击、拖拽、缩放与路线显示。
地图瓦片本身需要网络；无网络时显示本地坐标背景。

搜索包含本地高校名称、英文名、常见别名和直接经纬度跳转。
高校快捷点是校园参考中心，不是预先绘制的跑道。
此外会尝试高德公开网页建议接口；它可能限流或改变格式，不是有稳定性承诺的免 Key 服务。
正式 Web Service 输入提示 API 需要 Key，本程序没有嵌入他人的 Key 或认证凭证。
地图里的地名由地图服务绘制，未提供英文瓦片的地名无法由界面字典翻译。

## 前端接口

桌面使用 `window.pywebview.api`，浏览器预览使用同源 HTTP RPC。
每个调用返回 `{ok: true, data: ...}` 或 `{ok: false, error: {code: ...}}`。
前端以约 10 Hz 无重叠轮询状态，蓝点平滑绘制。运动线程默认每 0.8 秒尝试推进，真机发送未完成时等待。
原生桥接和 HTTP 等待均为 8 秒超时，超时后继续轮询；后台操作可能仍在处理，需等待状态更新。
状态按单调序列号接收，慢响应不会覆盖较新的操作状态。圈速和打卡历史使用滚动上限，累计数保持完整。

| 方法 | 参数与用途 |
| --- | --- |
| `bootstrap()` | 配置、状态及正在执行的支线路径 |
| `get_state()` | 状态、里程、速度、双坐标、倒计时、电量与系统保护结果 |
| `get_trace(after_sequence, session_id)` | GCJ-02 历史轨迹增量；会话更换或游标过期时返回重置，最多 3600 点 |
| `preview_track(points)` | GCJ-02 锚点转 WGS-84，返回平滑逆时针地图路径 |
| `save_track(points)` | 保存有效跑道，空数组表示清空模板 |
| `save_preferences(preferences)` | 保存语言、档位、目标或地图偏好，`route_offset_m` 依次为向东、向北的整数米数 |
| `search_places(query, language)` | 本地高校、经纬度与公开建议查询 |
| `recheck_time()` | 非阻塞触发系统时间检查 |
| `lock_start(payload)` | `points, profile, target_km, checks`；七项均为布尔真 |
| `start_cruise()` | 后端检查锁定状态与五秒驻留 |
| `pause()` / `resume()` | 请求减速休息 / 从休息逐步加速继续，后端校验阶段 |
| `hold_position()` | 在暂停慢走或收尾慢走期间停止移动，保持最后的模拟位置 |
| `submit_detour(points)` | 包含 `is_target` 的 GCJ-02 支线草稿 |
| `safe_settle(confirmation)` | 确认已提交成功并关闭应用，或确认放弃会话并关闭应用，再发送恢复指令 |
| `recover_previous_location()` | 连接会话标记记录的原设备，发送恢复指令 |

预览服务仅绑定 `127.0.0.1`，使用随机会话令牌、Host/Origin 检查与方法白名单。
只提供界面和明确允许的静态资源，不提供项目目录或私有 Python 方法。
